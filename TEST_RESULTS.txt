PatentLens AI v59 - separate core-key search tests

1. JavaScript syntax: app.js PASS, worker.js PASS, keyword_extractor.js PASS.
2. Query-plan policy: one core key = one query; no A+B concatenation in buildRetrievalSearchPlan.
3. Legacy input parser: [VI] "A" "B" is split into [VI] A and [VI] B.
4. Single quoted input: [VI] "A" becomes [VI] A (quotes removed).
5. Retrieval mode: frontend calls /api/search with mode=keyword_exact for every independent line.
6. VI query handling: backend may create an EN translation seed for the SAME key, then also tries the original VI key; it does not invent or concatenate a second key.
7. Candidate ranking remains document-level: results from all independent queries are merged by publication number and ranked using the full keyword fingerprint.
8. Provider cascade from v58 is preserved.

External provider availability is still runtime-dependent; these tests verify the code path and query construction, not guaranteed availability of third-party endpoints.
